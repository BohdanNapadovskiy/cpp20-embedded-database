# Embedded Database Engine — вбудований рушій бази даних

**Орієнтир:** 4 тижні (тижні 11–14)

## Мета
Зрозуміти двійкові формати, індекси, журналювання та відновлення узгодженого стану після збою.

## Функціональні вимоги
- Бібліотека key-value з API `open`, `put`, `get`, `erase`, `scan`, `close` + консольна оболонка.
- Власний append-only формат: версія заголовка, тип запису, довжини ключа й значення, контрольна сума; `erase` пише tombstone.
- Індекс ключів у пам'яті з відновленням при відкритті; compaction прибирає застарілі записи.
- Один процес і один writer. Межі довжин, перевірка пошкоджених записів, відкидання незавершеного хвоста після збою.

## Технології
`std::fstream` або WinAPI, `std::unordered_map` для індексу, `std::span`, `std::byte`; явна серіалізація чисел із фіксованим порядком байтів, CRC.

## План
1. Зафіксувати файловий формат і семантику успішного put. Не зберігати сирі C++-структури (padding).
2. Послідовний запис і читання з перевіркою розмірів, версії, контрольної суми.
3. Індекс і операції get/put/erase/scan. Відновлення індексу повним проходом журналу.
4. Compaction у новий файл і безпечне перемикання поколінь; старий файл — до підтвердження нового.
5. Fault injection: обрив на різних байтах запису й етапах compaction. Порівняння з еталонною map.

## Критерій готовності
- [ ] Після аварії відновлюється узгоджений префікс журналу
- [ ] Compaction зберігає всі актуальні пари
- [ ] Стійкість до знеструмлення — через `FlushFileBuffers` (flush потоку цього не гарантує)

## Розширення
Транзакції з commit-записом, B-tree або обмежений кеш сторінок. SQLite як сховище не використовувати.
